Privacy by design

Inspection data stays local by default.

UIScope documents no telemetry, analytics, crash uploads or user accounts. Captures and snapshots are stored in the local application data folder; network actions are limited and optional.

Data handling

What the application reads and stores.

UIScope reads the target UI only when you ask it to capture or inspect a window or device. It handles element trees, screenshots, window titles and process names needed for inspection.

Inspected content

Element trees and screenshots from the Windows window or Android device you select, along with related window and process information.

Local storage

Snapshots, database files, settings, helper files and rotating logs are stored under %LOCALAPPDATA%\UIScope on Windows.

Logs

The privacy document says element text, window titles, tree contents and device serials are not written to logs. Serial numbers are masked in the interface.

No cloud account

UIScope has no account or cloud sync system. Saved captures are not automatically uploaded or synchronized to a remote service.

Optional network requests

Two documented network actions.

Both are optional and occur through the app's network gateway.

Update check

When enabled, UIScope requests release metadata from the GitHub Releases API to check the available version and notes. It does not download an update automatically.

Platform-tools download

Only when you choose Download platform-tools, the app downloads Google's platform-tools archive from dl.google.com and verifies its checksum.

The documented update check is off by default in the Microsoft Store build and can be opted out of in Settings. No other routine telemetry or crash-upload channel is documented.
User control

Manage or remove local data.

Deleting a snapshot removes its files. The Settings screen's Clear all action removes the app's stored data, according to the repository privacy policy. You can also review the source and network inventory.
