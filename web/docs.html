UIScope documentation

Use the Windows desktop application to inspect Windows windows or a connected Android device through ADB. These sections preserve the in-app Help links and explain the current source-backed workflows.

Quick start

Current release status. The repository identifies version 1.0.2. Its installer is attached to the matching GitHub release; check the download status page or the official releases page. What changed: changelog.

Run from source

The project README documents a JDK 21 toolchain and the Gradle wrapper. This is the route for developers who want to run the source themselves.

  1. Install a JDK 21 distribution and Git on a supported Windows machine.
  2. Clone the official repository, then open a terminal in the cloned folder.
  3. Run gradlew.bat :app:run from Windows Command Prompt or PowerShell.

Use the repository README and build documentation if the Gradle build reports an environment-specific issue. Do not treat an older release asset as a build matching source version 1.0.2.

Inspect an Android device

  1. On the phone, open Settings, About phone and tap Build number seven times to unlock Developer options.
  2. In Developer options, turn on USB debugging. Connect the cable and choose File transfer if the phone asks for a USB mode.
  3. Accept Allow USB debugging? on the phone. Tick Always allow from this computer so it does not ask again.
  4. In UIScope, choose Android. If adb is not found, open Settings and choose Download platform-tools, or Browse to an adb you already have.
  5. Press F5 to capture. Hover the screenshot, click an element and read its rating.

About the download. When you choose Download platform-tools, UIScope first reads Google’s Android SDK package list to find the current release, then downloads Google’s official archive for your system, checks its size and checksum, and installs it in UIScope’s own folder. Nothing is installed anywhere else. The download is covered by Google’s Android SDK license.

Inspect a Windows app

  1. Choose Windows in UIScope. The helper checks itself on start; the status bar says “choose a window” when it is ready.
  2. Open Choose window and select any open window, or press Pick element (or Ctrl+Alt+P from any program), hover until the orange frame surrounds the control you want, and click it.
  3. UIScope captures that window and selects the element you clicked. Esc or a right-click cancels a pick.

How pick mode behaves

  • UIScope minimizes itself while you pick (so it does not hide the window you want) and comes back afterwards. Turn that off in Settings, Windows.
  • The click you make to choose an element is swallowed: it never reaches the other application.
  • Windows that run as administrator can only be inspected when UIScope itself runs as administrator.

Reading a selector rating

UIScope evaluates selector candidates against the captured element index and displays match counts, reliability guidance, warnings and a verdict. Treat that verdict as evidence for the current capture, not a guarantee that a selector will remain stable across app versions, sessions or data.

Copy the bare selector with Ctrl+Shift+C, or the whole snippet for the framework you chose with Ctrl+Shift+K. Android targets: Appium (Python, Java), uiautomator2, UI Automator (Kotlin), Maestro, XPath. Windows targets: pywinauto, FlaUI, AutoHotkey v2, PowerShell UI Automation.

Snapshots and Compare

Ctrl+S saves the current capture as a snapshot. Snapshots reopen offline from the Snapshots screen and export as a .uiscope bundle another UIScope can import. Compare diffs any two captures, live or saved, and lists what was added, removed, changed or moved; the result exports as JSON or text.

Settings and data

UIScope keeps everything under %LOCALAPPDATA%\UIScope: settings.json, snapshots, db, logs, the helper under helper and a scratch folder tmp. Settings has buttons that open the logs and snapshots folders.

To change the pick shortcut, close UIScope and edit pickHotkey in settings.json, for example "Ctrl+Shift+F9". A shortcut needs at least one of Ctrl, Alt, Shift or Win plus a key. If another program already uses it, UIScope tells you and leaves the shortcut off.

Troubleshooting

Start with the status bar and the banner above the screenshot: they name the problem. Copy details on any error banner copies the exact code and message for a bug report.

Android problems

“adb not found”

UIScope looks at the path you saved, ANDROID_SDK_ROOT and ANDROID_HOME, the default Android Studio folder, your PATH, a few well-known folders and its own copy. None had a working adb.

  • Open Settings and choose Download platform-tools, or Browse to your adb.exe.
  • If the download fails with a network code, check your connection or proxy and try again. UIScope never installs anything whose checksum does not match.
  • Security software sometimes quarantines adb.exe. Restore it or exclude the UIScope folder.
“No device” although the phone is connected
  • Use a data cable, not a charge-only one, and choose File transfer on the phone.
  • Check that USB debugging is on (see the steps above).
  • On Windows the phone may need its maker’s USB driver. If it appears with a warning icon in Device Manager, install the driver for your model.
“Device is not authorized”

The phone is waiting for you to accept Allow USB debugging?. Unlock it and accept. If the prompt never appears, open Developer options, choose Revoke USB debugging authorizations, and reconnect the cable.

“Device is offline”, or devices flip between device and offline

Usually two adb servers are fighting. Close other tools that start adb (Android Studio, scrcpy, another copy of platform-tools) or point UIScope at the same adb.exe they use with Settings, Browse. Replugging the cable also helps.

The capture fails on one screen
  • The screen is secure. Banking, password and DRM screens block screenshots by design. UIScope says so instead of showing a blank image.
  • uiautomator is busy. Another automation tool (an Appium or uiautomator2 server, for example) holds the accessibility service. Stop it and capture again.
  • Idle timeout or empty root. The app was still animating. Wait a second and press F5; turning off animation scales in Developer options helps.

Windows problems

“Windows inspection isn’t available” (the helper)

UIScope uses a small helper program, UIScope.Helper.exe, to read other programs through UI Automation. This message means the helper did not start or did not answer.

  1. Press Retry once. If it keeps failing, choose Copy details and read the last lines: they include what the helper wrote and whether it exited.
  2. Run the helper’s own self-test. Open a terminal and run: 
    "%LOCALAPPDATA%\UIScope\helper\UIScope.Helper.exe" --selftest
    It lists what works (UI Automation, the window list, a capture of one open window with timing, screenshots, the mouse hook) and prints the reason for anything that does not.
  3. If the file is missing or the self-test cannot start, your security software probably removed it. Restore UIScope.Helper.exe from quarantine or add an exclusion for %LOCALAPPDATA%\UIScope, then restart UIScope.
  4. The helper needs the .NET Framework 4.8 runtime, which Windows 10 1809 and newer include.
“That window runs as administrator”

Windows does not let a normal program read an elevated one. Close UIScope, start it with Run as administrator, and capture the window again.

“The window is minimized”

A minimized window has no picture to capture. Restore it, then press F5.

“This app exposes little accessibility information”

Some toolkits publish very little to UI Automation until asked:

  • Chromium and Electron (Chrome, Edge, VS Code, Slack): start the app with --force-renderer-accessibility.
  • Qt: set QT_ACCESSIBILITY=1 before starting it.
  • Java Swing: enable the Java Access Bridge with JABSwitch.exe /enable.
“The tree was cut at the limits”

Very large windows are read for up to 25 seconds or 10,000 elements, then UIScope shows what it has and says so. Select a smaller part of the app, or close panes you do not need, and capture again.

The pick shortcut does nothing, or UIScope says it is already used

Another program owns Ctrl+Alt+P. Use the Pick element button, or choose a different combination in settings.json (see Settings and data). You can also turn the shortcut off in Settings, Windows.

The highlight does not line up with the element

This is almost always display scaling on a second monitor. UIScope uses physical pixels everywhere, so please report it with the diagnostics below and the scaling of each monitor.

Report a bug

  1. Open Settings and choose Copy diagnostics. It contains versions, the adb and helper status and no screen content.
  2. Open the logs folder from Settings. Logs never contain element text, window titles or device serials.
  3. Create an issue at github.com/TITANICBHAI/UIScope-jvm/issues and paste the diagnostics.
